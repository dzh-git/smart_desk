# 0.8.0 原型阈值标定

本流程只生成 `PROVISIONAL` 阈值，用于演示和内部可行性验证，不估计或声明
正式系统的误接受率、误拒绝率或安全等级。

## 样本安排

- 选择3名已注册人员和2名未注册人员。
- 使用正常光、较亮环境、较暗环境。
- 每人每种环境验证5次，共 `5 × 3 × 5 = 75` 次。
- 每次记录自然光和补光阶段的Top1、Top2、分差、5帧Top1一致数及最终状态。
- 已注册人员额外记录本人分数和其他注册人员最高分；未注册人员记录所有注册
  人员中的最高分。

建议开启Debug诊断；它会把112×112对齐图和 `metrics.jsonl` 写入App私有目录。
测试结束后导出分析，并立即在页面中清除诊断数据。

## 阈值规则

分别观察：

```text
最低本人Top1分数
最高错误身份分数
最高未注册人员分数
```

只有最低本人分数明显高于两类错误最高分时，才在间隔内选择偏保守阈值。
如果分数重叠，保持 `CALIBRATION_PENDING`，不得通过降低阈值强行启用。

应用阈值后状态必须为：

```text
thresholdStatus = PROVISIONAL
verificationLevel = PROTOTYPE
```

`VALIDATED` 状态不能由当前页面设置。它必须等待更多未注册人员、独立样本和
多现场测试后，在未来版本中通过受控流程启用。

## 只有一名人员时

只有一名注册人员时，可以使用本人历史图片和许可明确的网络肖像进行静态代理
测试，检查模型、质量门槛和明显误匹配，但必须保持
`CALIBRATION_PENDING`。静态图片不能替代CameraX实时5帧采集，也不能产生
`PROVISIONAL`阈值。

当前单人代理测试方法和结果见
静态图片原型报告已退出当前验收依据；阈值只能使用本页规定的 75 次现场数据
重新计算。
