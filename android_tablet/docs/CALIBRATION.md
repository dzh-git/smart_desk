# 0.8.0 原型阈值标定

本流程只生成 `PROVISIONAL` 阈值，用于演示和内部可行性验证，不估计或声明
正式系统的误接受率、误拒绝率或安全等级。

## 样本安排

- 选择3名已注册人员和2名未注册人员。
- 使用正常光、较亮环境、较暗环境。
- 每人每种环境验证5次，共 `5 × 3 × 5 = 75` 次。
- 每次记录自然光和补光阶段的Top1、Top2、分差、5帧Top1一致数及最终状态。
- 已注册人员额外记录本人分数和其他注册人员最高分；未注册人员记录所有注册
  人员中的最高分。

现场采集与分析仍按受控标定流程执行；诊断页只展示设备和摄像头能力。阈值结果
统一回到主持人人脸模板管理页确认，当前原型输入默认显示 `0.55`。测试结束后应
立即清除 App 私有目录中的对齐图和 `metrics.jsonl`。

## 阈值规则

分别观察：

```text
最低本人Top1分数
最高错误身份分数
最高未注册人员分数
```

只有最低本人分数明显高于两类错误最高分时，才在间隔内选择偏保守阈值。
如果分数重叠，保持 `CALIBRATION_PENDING`，不得通过降低阈值强行启用。

应用阈值后状态必须为：

```text
thresholdStatus = PROVISIONAL
verificationLevel = PROTOTYPE
```

`VALIDATED` 状态不能由当前页面设置。它必须等待更多未注册人员、独立样本和
多现场测试后，在未来版本中通过受控流程启用。

## 阈值与模板数量

主持人模板管理页允许在没有本机模板或只有一名人员时确认默认的 `0.55`
`PROVISIONAL` 阈值，因为该配置只绑定模型哈希与处理流水线版本。新增、更新、
删除或清空本机模板不会使阈值失效；模型或流水线变化仍会恢复
`CALIBRATION_PENDING`。

模板数量独立不代表阈值已经通过正式标定。席位按已分配人员执行 1:1 验证，一个
模板即可启动；正式阈值仍须使用本页规定的 75 次现场数据重新计算和验证。
Top2 与分差只作为多人对比诊断信息，不参与 1:1 放行。
