# 必须人工/实物完成的验收

## 使用规则

日常现场操作优先按
[四个简化场景](FIELD_VALIDATION_QUICKSTART.md)执行；本文件用于记录详细证据和
失败判定，不要求操作者逐项阅读后才开始。

本清单是剩余非机器可验证工作的唯一汇总。自动测试、Mock、模拟器、旧原型报告
或静态图片均不能把本页项目改为通过。每项必须记录提交、App/固件/模型版本、
日期、操作者、设备序列号/席位和原始日志路径；失败先保留现场，再按复现步骤建
问题，禁止降低阈值或关闭认证制造通过。

建议证据目录（不提交人脸/凭据）：

```text
field-validation/<YYYY-MM-DD>/
├─ manifest.md
├─ android/
├─ backend/
├─ esp32/
├─ network/
├─ speech/
└─ results/
```

## HV-01 Redmi K60 安装和权限

- 准备条件：已审核 Debug APK、本地研究模型、ADB、充足电量、旧数据备份。
- 操作步骤：`adb install -r <apk>`；启动 App；授予相机/麦克风；拒绝后再从系统
  设置授权；执行 `adb shell dumpsys package com.smartdesk.tablet` 核对
  `versionName=0.8.0`。
- 预期结果：覆盖安装/冷启动成功；首次授权、拒绝和再次授权均有明确状态，无
  崩溃；Release 调试不可用。
- 失败表现：签名冲突、安装失败、权限死循环、空白页、崩溃或令牌回显。
- 保存日志：APK SHA-256、dumpsys、安装输出、logcat、权限页截图。

## HV-02 WebView 正式席位页面

- 准备条件：中央主机固定 IP，8000/5173 可达，平板已配置 seat 1。
- 操作步骤：冷启动；核对加载 `/seat/1`；测试错席 URL/外部链接被拦截；断开
  中央服务后进入诊断页，再恢复网络。
- 预期结果：正式会议页唯一；seatId 正确；HTTP/会议 WebSocket 可用；超时/
  离线/服务器错误清晰，恢复后自动重载。
- 失败表现：加载第二套会议页、任意外站可用 Bridge、错席、无限白屏或恢复失败。
- 保存日志：WebView/chromium logcat、后端访问日志、页面与错误态截图。

## HV-03 CameraX 前置摄像头

- 准备条件：HV-01/02 通过，前置摄像头无遮挡。
- 操作步骤：从正式页启动/停止 5 次；背景/恢复；旋转或锁屏恢复；0、1、2 人
  入镜；观察 overlay 与网页事件。
- 预期结果：使用前置摄像头；`NO_FACE/ONE_FACE/MULTIPLE_FACES` 正确；每次
  停止和 Activity 暂停都释放摄像头，无线性内存增长。
- 失败表现：黑屏、错误镜头、多人仍验证、相机被占用、停止后继续处理或崩溃。
- 保存日志：CameraX/SmartDeskTablet logcat、内存快照、5 次启停记录、视频。

## HV-04 75 次开放集标定

- 准备条件：3 名已注册人员、2 名未注册陌生人、正常/亮/暗 3 种光照；各人知情
  同意；日常眼镜状态纳入样本。
- 操作步骤：每人每种光照 5 次，共 `5 × 3 × 5 = 75`；每次记录自然光与补光
  Top1、Top2、margin、5 帧一致数、最终状态。按
  [CALIBRATION](../../android_tablet/docs/CALIBRATION.md) 分析。
- 预期结果：本人最低 Top1 明显高于错误身份与陌生人最高分，且 margin≥0.05、
  5 帧至少 4 帧一致；只允许设置 `PROVISIONAL/PROTOTYPE`。
- 失败表现：分数重叠、错人 Top1、多人/质量门未挡住、为通过而降低阈值。
- 保存日志：75 行匿名化 CSV、阈值分析、模型/模板版本、诊断 JSON；不上传照片。

## HV-05 陌生人误接受与翻拍风险

- 准备条件：HV-04 数据、至少 2 名陌生人；测试经授权，当前无活体检测。
- 操作步骤：每个陌生人完成三光照测试；额外用授权照片/屏幕翻拍做攻击性检查；
  观察是否产生 `VERIFIED` 或调用签到。
- 预期结果：陌生人均为 `UNKNOWN/RETRY_REQUIRED`，后端无签到写入；任何误接受
  都阻断自动签到发布。
- 失败表现：陌生人或翻拍被接受、生成 `personId` 并签到。
- 保存日志：尝试矩阵、eventId、Top1/Top2、后端事件与屏幕录像。

## HV-06 ESP32 烧录

- 准备条件：目标 ESP32 板、数据线、PlatformIO、独立 DeviceConfig、串口号。
- 操作步骤：编译；记录二进制哈希；上传；115200 打开串口；冷启动和看门狗
  重启；核对设备/席位/固件版本。
- 预期结果：启动无 boot loop，hello 通过认证和版本门禁，日志无令牌。
- 失败表现：烧录失败、持续复位、错席、认证失败、明文令牌日志。
- 保存日志：PlatformIO 构建/上传、固件哈希、完整串口启动日志。

## HV-07 PIR 接线和人体感应

- 准备条件：按固件引脚接线，稳定供电，HV-06 通过。
- 操作步骤：空席/入座/离座各 10 次；记录原始 PIR、合并占用状态和时间；观察
  环境运动误触发。
- 预期结果：人体变化被稳定上报，不影响其他席位，抖动不产生重复签到。
- 失败表现：空席持续占用、漏检、快速抖动、错误席位事件。
- 保存日志：接线照片、串口、后端 occupancy 事件、10 次记录。

## HV-08 VL53L0X 距离

- 准备条件：I2C/供电正确，量尺或固定距离目标。
- 操作步骤：在阈值上下及滞回区间各测 10 次；遮挡/移除传感器；记录
  `distance_mm` 和故障上报。
- 预期结果：距离合理、滞回防抖有效、断线为传感器错误且系统安全降级。
- 失败表现：恒定异常值、阈值振荡、总线故障导致重启或错误入座。
- 保存日志：接线、实测距离表、串口与后端传感器诊断。

## HV-09 WS2812B 灯带和供电

- 准备条件：独立足额电源、共地、必要的电平转换/限流，灯珠数和引脚正确。
- 操作步骤：逐个触发 IDLE、待签到、WELCOME、服务、ERROR；0/目标亮度切换；
  连续全负载并测电压/温度。
- 预期结果：模式/亮度正确，ACK 的 `current_mode` 与实物一致；断网进入安全
  ERROR；无闪烁、掉压或过热。
- 失败表现：颜色/席位错、ACK 假成功、ESP32 复位、导线/电源过热。
- 保存日志：接线/电源规格、视频、命令 ID/ACK、测量表。

## HV-10 真实 Wi-Fi 重连

- 准备条件：中央主机、平板、ESP32、可控 AP，时钟同步。
- 操作步骤：关闭/恢复 AP；制造弱信号；重启后端；分别断开平板与 ESP32；
  每种至少 3 次。
- 预期结果：指数退避、无重连风暴；离线超时正确；重连后同步状态，灯态安全，
  不重复 occupancy/签到。
- 失败表现：永不恢复、重复事件、错误在线、凭据泄露或灯态卡死。
- 保存日志：AP、后端、logcat、串口时间对齐日志和恢复耗时。

## HV-11 WebView 真实麦克风

- 准备条件：HV-01/02，通过 HTTPS 或受控局域网策略评估；活动会议和演讲席。
- 操作步骤：可信席位请求麦克风；外部/错席页请求；开始/停止 5 次；背景/恢复；
  切换演讲席和断开语音 WebSocket。
- 预期结果：仅可信席位获准；16 kHz 单声道 PCM16 到达服务端；旧演讲席立即
  停止；所有异常释放资源且用户可见。
- 失败表现：外部页获权、双席同时上传、麦克风占用不释放、无错误提示。
- 保存日志：Android 权限/logcat、浏览器事件、后端 speech trace（不保存原始
  语音，除非另获许可）。

## HV-12 30 分钟语音稳定性

- 准备条件：真实会议房间、允许的测试语音、语音模型已安装、追踪开关受控。
- 操作步骤：连续 30 分钟中英语音，包含静音、切席、短断网；每 5 分钟记录
  内存、队列、首 token/最终文本延迟。
- 预期结果：无崩溃、线性内存/队列增长、丢失最终句或资源泄漏；恢复后新
  utterance 正常。
- 失败表现：字幕永久卡住、重复终句、音频继续上传、延迟持续恶化。
- 保存日志：前后端 trace、资源曲线、utterance 统计和时间线。

## HV-13 单席连续 20 次完整流程

- 准备条件：HV-01–12 对应单席项已通过，测试数据库与清理步骤固定。
- 操作步骤：按 [ONE_SEAT_RUNBOOK](ONE_SEAT_RUNBOOK.md) 完成 20 个独立轮次；
  至少包含重复身份事件、页面刷新、平板/ESP32断线、后端重启。
- 预期结果：20/20 入座→待签到→本地识别→签到→同步→灯光 ACK；数据库无重复
  绑定或脏状态。
- 失败表现：任一轮需手工改库/重启才能继续、状态分叉、重复签到或错误灯态。
- 保存日志：每轮 eventId、meeting/attendee、commandId、恢复时间和总表。

## HV-14 九席同时在线

- 准备条件：九套设备、seat 1 门禁通过、AP 容量与中央主机资源已评估。
- 操作步骤：按 [NINE_SEAT_DEPLOYMENT](NINE_SEAT_DEPLOYMENT.md) 分批上线；
  九席在线 30 分钟；逐席和并发触发；切演讲席；重启一台设备/AP/后端。
- 预期结果：18 个设备通道正确绑定并恢复；无串席、广播风暴、重复签到或音频
  多源；管理端状态完整。
- 失败表现：错席、设备被另一席令牌接受、AP/主机过载、恢复造成状态分叉。
- 保存日志：hardware status 快照、AP/主机资源、九席矩阵、前后对比视频。

## HV-15 现场供电、温度和长时运行

- 准备条件：最终线束、外壳、电源、灯带长度、九席同时工作，安全负责人在场。
- 操作步骤：典型会议负载和灯带高负载各持续运行；测中央主机、平板、ESP32、
  电源和线束温度/电压；检查充电、接地、保险和通风。
- 预期结果：全部在器件/场地批准范围内，无降频、重启、掉压、异味或触摸危险。
- 失败表现：过热、鼓包、线束发热、反复掉线、传感器漂移或电源保护触发。
- 保存日志：器件规格、测量时间序列、热成像/照片、异常与整改记录。
