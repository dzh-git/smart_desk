## 现场完成顺序

| 阶段 | 需要准备 | 完成标准 |
|---|---|---|
| 1. 正式网络 | 独立 AP、固定中央主机地址、18 个终端的 DHCP 保留、受控 WLAN | Seat 1、Seat 9、后端 8000 和前端 5173 均稳定可达，断网恢复无风暴 |
| 2. 九台平板 | 同一 SHA-256 APK；Seat 1 主持人；Seat 2–9 参会席；逐台贴纸 | 每台一键部署报告 PASS，MIUI 自启动/后台无限制人工确认，冷启动 5 次回到正确页面 |
| 3. 九个 ESP32 | 每席唯一 `device_id`/Token、同一固件、独立忽略的 `DeviceConfig.h` | 逐席烧录、hello/版本认证、灯带 ACK、断电与看门狗恢复通过 |
| 4. 人脸与会议 | 九席人员分配、现场真人、现有原型安全等级 | 正确人脸签到、错误人脸拒绝、离席再签到、无串席；保存匿名化证据 |
| 5. 灯光与电气 | 最终 WS2812B、足额电源、共地、线束、保险与散热 | IDLE/WELCOME/服务/发言/ERROR 均只作用目标席，满载无掉压、复位或过热 |
| 6. 联合并发 | 九台平板、九个 ESP32、真实 AP 和中央主机 | 同时在线 30 分钟，逐席/并发操作、切发言席、投票、服务和恢复全部通过 |
| 7. 长时与发布 | 真实麦克风、30 分钟中英语音、备份/回滚、许可证审核 | 无字幕卡死/队列增长；备份恢复和回滚演练通过；适用人工项签字 |

详细动作和证据格式以
[HUMAN_VALIDATION_REQUIRED](HUMAN_VALIDATION_REQUIRED.md) 为准。当前最关键的
外部阻塞是 ESP32 尚未连接，因此 HV-06、HV-07、HV-09 以及真实平板—灯光闭环
尚不能完成；其次是正式独立 AP 与九套实体设备尚未到齐。

## 极简部署批次

1. 中央主机固定地址并启动 SmartDesk。
2. 平板按 `Seat 1 → Seat 2 → Seat 3–9` 逐台双击一键包；脚本已在 Windows
   PowerShell 5 和 PowerShell 7 执行 Dry Run，并验证 APK SHA-256。
3. ESP32 用同一固件、每席独立配置烧录并贴签。
4. 每增加一席先验收设备映射与灯光，再扩下一席。
5. 九席齐备后执行 30 分钟联合验收和故障恢复，不在失败状态继续复制。

## 不能省略的人工项

- 平板首次 USB 调试授权、平板内输入两个口令、MIUI 自启动和后台策略。
- 每台实体设备的 Seat ID/设备 ID/贴纸三方核对。
- ESP32 烧录、接线、供电与真实灯效观察。
- 真人、真实麦克风、九席 Wi-Fi 并发、温度和长时运行。
- 商业模型许可、活体检测风险、TLS/管理授权与正式发布审批。
