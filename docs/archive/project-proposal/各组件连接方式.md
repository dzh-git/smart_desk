这个问题已经进入工程设计层面了。

> **【权威拓扑】** 正式部署采用 `distributed` 模式：每个 Arduino Nano 经 USB 串口连接**本座位的 Windows 终端**；各终端通过 Seat Edge Agent、WebSocket/REST 与中央主机通信，灯光命令按 `seat_id` 经网络下发。中央主机不直连 Arduino 串口。
> 座位数：9 个 Windows 终端（seat 1=主持人，seat 2..9=参会）+ 1 台中央主机。单机/台架联调可改用 `central` 模式，由中央主机直接管理 1–9 号串口。

如果按照我们前面最终确定的架构：

```text
中央服务器（桌体内部）
    │
    ├── 86寸中央沙盘屏（直连）
    │
    └── 24口交换机
            │
            ├── 主持人终端（seat 1，独立 Windows）
            └── 8个参会终端（seat 2..9）

中央服务器运行：
FastAPI
SQLite
WebSocket
ASR
翻译
```

并且：

> 主持人终端不是中央服务器第二显示器，而是通过网络远程控制中央服务器（类似指挥中心模式）。

那么我建议如下接口规划。

## USB HUB

> **【更新】** Arduino **不再**接入中央 USB HUB，而是各自连接本座 Windows 终端的 USB 口（见 §六）。中央 USB HUB 仅用于中央外设/调试/未来扩展，不再承担 Arduino 汇聚。

原计划（已废弃）：

```text
Arduino1
Arduino2
...
Arduino9    ← 全部接中央 USB HUB
```

---

因此：

```text

4×视频输出
8×USB
```
