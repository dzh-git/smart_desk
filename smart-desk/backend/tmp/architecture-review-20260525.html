架构深化候选 (Deepening Candidates)

1. 提取 useSeat 深层模块

Strong
涉及文件
composables/useSeat.js (新建)
ServicePanel.vue (修改)
VotingPanel.vue (修改)
AttendeePanel.vue (修改)
App.vue (修改)

问题: seat_id: 1 硬编码在 ServicePanel:47、VotingPanel:165、AttendeePanel:55。8座平板的每个座位都显示相同内容，无法区分。没有 URL 参数 ?seat=N 的解析逻辑。

方案: 创建 useSeat() 组合式函数 — 解析 ?seat=N URL 参数，持久化到 localStorage，通过 provide/inject 全局注入。每个 Panel 通过 inject('seatId') 获取当前座位号。

收益: 座位的全部知识（URL 解析、持久化、默认值）集中在一处。杠杆: 所有 4 个 Panel 和一个全局状态源。切换座位只需改 URL。

Before — 浅层

// 每处各自硬编码
ServicePanel: seat_id: 1
VotingPanel: attendee_id: 1
AttendeePanel: seat_id: 1

// 无 URL 感知
// 无全局状态
// 8座无法区分

After — 深化

// useSeat.js — 单一深层模块
export function useSeat() {
  const seatId = ref(
    Number(route.query.seat)
    || Number(localStorage.seatId)
    || 1
  )
  watch(seatId, v =>
    localStorage.seatId = v)
  provide('seatId', seatId)
  return { seatId }
}

// 各组件: inject('seatId')

依赖类别: In-process — 纯 URL + localStorage，无 I/O，可直接深化。

2. 提取 BaseDialog 深层模块

Worth exploring

问题: 对话框/遮罩模式在 HomeView、AttendeePanel、VotingPanel 中重复出现 3 次。每次复制完整的 overlay + dialog DOM 结构和关闭逻辑。

方案: 提取 BaseDialog 组件 — 封装 overlay 点击关闭、ESC 键关闭、过渡动画、插槽。接口: { show: Boolean, title: String } + #default + #actions 插槽。

收益: 对话框全部行为（关闭、ESC、动画）集中一处。删除测试: 删除 BaseDialog → 关闭逻辑在 3 处重新出现 → 证明它值得存在。

Before — 重复 3 次

<div v-if="show" class="overlay"
     @click.self="show=false">
  <div class="dialog card">
    <h2>...</h2>
    ...form...
    <div class="dialog-actions">
      <button @click="...">取消</button>
      <button @click="...">确认</button>
    </div>
  </div>
</div>

<style scoped>
.overlay { ...固定定位... }
.dialog { width:420px; ... }
.dialog-actions { ...flex... }
</style>

After — 单一模块

<BaseDialog
  v-model="show"
  title="创建会议"
>
  ...form...
  <template #actions>
    <button @click="...">取消</button>
    <button @click="...">确认</button>
  </template>
</BaseDialog>

依赖类别: In-process — 纯 UI，可直接深化。

Top Recommendation

优先处理 Candidate 1 (useSeat) + Candidate 4 (8人种子数据)。
Candidate 1 是阻塞项 — 多座位适配是 Phase 1 的核心目标，所有其他工作都依赖它。
Candidate 4 是验证前提 — 没有 8 人数据，无法做 8 窗口联调。
Candidate 2 (BaseDialog) 和 Candidate 3 (CSS 去重) 是代码质量提升，可在实现 1+4 后跟进。
