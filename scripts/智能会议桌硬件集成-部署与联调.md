## 二、配置（部署前必改）

编辑 `config/smartdesk.integration.json`：

```
arduino.port          实际 COM 口（如 COM3/COM7），默认值 COM5 为占位
arduino.baudrate      115200（勿改）
arduino.write_timeout_seconds  1.0
arduino.heartbeat_interval_seconds  5.0（心跳 PING 周期）
arduino.reconnect_interval_seconds  3.0（断开后重连间隔）
gesture.status_ws_url 手势服务地址（默认 ws://127.0.0.1:8765）
```

- 不插 Arduino 时，把 `arduino.enabled` 设为 `false`，后端照常启动、业务 API 不受影响。
- 改 COM 口只需改配置文件，无需动代码。

## 四、硬件与现场注意

### 4.1 COM 口
- Arduino Nano 每次插拔可能变 COM 口；以「设备管理器 → 端口」为准。
- 若端口被占用（如串口监视器未关），后端会反复重连并打印警告，关闭占用程序即可。

### 4.2 供电
- WS2812B 60 颗灯，单颗全白峰值约 60mA；协议已把亮度硬上限裁到 80/255，日常电流可控。
- 若灯带长度大或现场闪烁/偏色，务必使用 **独立 5V 外接电源**（USB 供电不足会拖垮逻辑电平），并确保灯带 GND 与 Nano GND 共地。

### 4.3 摄像头占用
- 手势控制器独占摄像头（cv2）。若同时运行其他调用摄像头的程序（如会议软件、另一 OpenCV 窗口），会报 `camera open failed`。
- 联调手势时，先关闭其他占用摄像头的进程。

## 五、验收步骤（灯效链路）

打开管理端 `http://localhost:5173/admin`，依次操作并观察桌面灯带 / 管理端「硬件状态」面板：

1. 创建会议并「开始会议」→ 灯效 `MEETING_ACTIVE`（蓝白呼吸）。
2. 新增/切换议程 → `AGENDA_ACTIVE`（柔和白、中心亮）。
3. 创建投票并「开始投票」→ `VOTE_OPEN`（黄色脉冲）。
4. 结束投票 → 回到 `MEETING_ACTIVE`。
5. 发起服务呼叫（如茶水）→ `SERVICE_CALL`（橙红闪烁）。
6. 结束会议 → `MEETING_ENDED`（绿色收束）→ 自动回到 `IDLE`（青色呼吸）。
7. 有人落座（PIR 触发）→ `EVENT PIR 1` → `WELCOME`（青绿流动）；离座 `EVENT PIR 0` → 回 `IDLE`。

也可直接用串口监视器向 Arduino 发命令验证固件：
```
PING              -> PONG
SET_MODE WELCOME -> OK SET_MODE WELCOME（青绿流动）
SET_BRIGHTNESS 200 -> OK SET_BRIGHTNESS 200（固件内部裁到 80）
OFF              -> OK OFF（灯带全灭）
SET_MODE BAD     -> ERR UNKNOWN_MODE
```

## 六、故障排查

- 管理端「硬件状态」Arduino 显示离线：检查 COM 口配置、串口是否被占用、Nano 是否已烧录新固件。后端日志会打印 `[Arduino] connected / connection lost`。
- 灯效不变化：确认 `arduino.enabled=true` 且后端已 `start()`；查看后端启动日志有无 `Hardware init failed`。
- 有人落座不变灯：确认当前模式为 `IDLE`（会议进行中 PIR 被忽略，符合协议 §4.3）；PIR 接线与 `SENSOR_PIN=8` 一致。
- 手势服务离线：确认手势进程已启动、8765 端口未被占用；`GET /api/hardware/status` 的 `gesture.online` 字段反映 TCP 探测结果。
