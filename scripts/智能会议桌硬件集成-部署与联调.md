# 智能会议桌硬件集成、部署与联调

> 适用范围：9 个完整席位（seat 1 为主持人位，seat 2–9 为参会位）。
> 权威协议：`arduino_nano_controller/protocol.md`；配置：`config/smartdesk.integration.json`。

## 1. 部署拓扑

系统有两种支持的部署模式；二者的业务事件和 Arduino 串口协议相同，只是串口归属不同。

| 模式 | 用途 | 串口归属 | 配置 |
|---|---|---|---|
| `central` | 单机台架、现场联调 | 中央主机直接打开 1–9 号 Nano 的串口 | 当前配置默认值 |
| `distributed` | 正式分布式部署 | 每席 Windows 终端运行 Seat Edge Agent，管理本席 Nano | `deploy_mode: "distributed"` |

在 `distributed` 模式下，中央主机不打开任何 Arduino 串口；Seat Edge Agent 连接 `/ws/seat/{seat_id}`，接收灯光命令并上报 `EVENT PIR` 状态。手势控制器始终是中央主机上的独立进程，不参与会议业务或 Arduino 控制链路。

## 2. 部署前配置

编辑 `config/smartdesk.integration.json`。

- `deploy_mode`：台架联调用 `central`，正式每席终端部署用 `distributed`。
- `arduino.seats`：仅 `central` 模式使用，必须覆盖 `"1"` 到 `"9"` 的实际 COM 口。
- `lighting.demo_seat_id`：单灯带演示时设为目标席位（当前为 `1`）；全席联调时设为 `null`。
- `gesture.enabled` 与 `gesture.status_ws_url`：仅控制管理端的手势服务在线探测；默认地址为 `ws://127.0.0.1:8765`。

每个分布式席位终端复制 `new_coding_desk/seat_agent/seat_agent_config.example.json` 为 `seat_agent_config.json`，并填写该席位的 `seat_id`（1–9）、`serial_port` 和中央主机 WebSocket 地址。座位身份由此配置决定，**不是**由 Arduino EEPROM 决定。

## 3. 启动顺序

1. 将相同的 Arduino 固件烧录到 9 个 Nano，完成 SR505、VL53L0X、WS2812B、独立 5V 灯带电源和共地接线。
2. 启动主程序：在 `new_coding_desk/` 运行 `start.bat`，或分别启动 `uvicorn backend.main:app` 与前端 Vite。
3. 仅在 `distributed` 模式下，在每个席位终端从 `new_coding_desk/` 运行 `python -m seat_agent`。
4. 如需手势控制，在 `smartdesk_gesture_controller/` 运行 `start_gesture.bat`；先用 `start_gesture_dry_run.bat` 校验相机、模型与动作映射。
5. 打开管理端 `http://localhost:5173/admin`，检查 `GET /api/hardware/status` 中 1–9 号席位与手势服务状态。

## 4. 灯效验收链路

在管理端依次执行并观察目标席位的灯带和硬件状态：

1. 开始会议：`MEETING_ACTIVE`。
2. 更新议程：`AGENDA_ACTIVE`。
3. 开始与结束投票：`VOTE_OPEN`、`VOTE_CLOSED`，随后按业务规则恢复。
4. 创建服务呼叫：对应席位进入 `SERVICE_CALL`，10 秒后恢复前一模式。
5. 当前发言席上传音频：对应席位进入 `AI_SPEAKING`；停止发言后恢复。
6. 在 `IDLE` 状态下触发复合入座条件：收到 `EVENT PIR 1`，对应席位播放一次 `WELCOME`；离座 `EVENT PIR 0` 后回到 `IDLE`。
7. 结束会议：`MEETING_ENDED`，随后回到 `IDLE`。

可用 Arduino IDE 串口监视器（115200、换行符 NL）验证固件：

```text
PING                  -> PONG
SET_MODE WELCOME      -> OK SET_MODE WELCOME
SET_BRIGHTNESS 200    -> OK SET_BRIGHTNESS 200（固件实际裁至 80）
OFF                   -> OK OFF
SET_MODE BAD          -> ERR UNKNOWN_MODE
```

## 5. 现场安全与排障

- WS2812B 灯带必须使用独立 5V 电源，Nano 与灯带 GND 必须共地；固件亮度上限为 `80/255`。
- `EVENT PIR 1` 是 SR505 高电平与 VL53L0X 平均距离小于 100 mm 的复合结果；不要以单独 PIR 信号判断故障。
- `central` 模式下 Arduino 离线时，检查 COM 口、串口占用和配置；`distributed` 模式下，先检查对应 Seat Edge Agent 的 WebSocket 连接。
- 手势进程独占摄像头。相机打开失败时，先关闭会议软件、浏览器或其他 OpenCV 进程。
- 硬件不可用不会阻止主程序启动；以日志和 `/api/hardware/status` 定位离线席位。
